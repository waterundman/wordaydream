## 2. 数据来源选型：为什么不用 LLM 凭记忆生成

原计划（方案 A）是「按 CEFR-J 公开词表知识生成 4 级 ~4000 词」。执行时改为**获取真实开源数据集并对齐**，理由：

1. GitHub 在本机**完全不可达**（直连与 `127.0.0.1:10808` 代理均返回 000），CEFR-J / EVP 原始文件无法取得；
2. 但 npm registry 可达 —— 探查发现两个 MIT 许可数据集，组合后恰好覆盖全部所需字段。

| 数据源 | npm 包 | 许可 | 提供字段 |
|---|---|---|---|
| Oxford 3000/5000 频段分级英语词 | `@polyglot-bundles/en-word-lists` (0.4.3) | MIT | lemma / pos / CEFR / 语义分类 |
| ECDICT 英汉词典数据集 | `ecdict` (0.0.4, 源自 skywind3000/ECDICT) | MIT | 中文释义 / COCA 词频 / 考纲标签 |

**join 覆盖率 4070/4070 = 100%** —— 无需为任何词兜底编造释义。

> 决策要点：真实数据集（含 100% 中文释义）远优于凭记忆生成的词形，也避免了 4000 条不可核验的释义。上游数据不入库（`npm pack` 获取，`.tmp-wl/` 已 gitignore），生成脚本可复现。

## 3. 产出规模与派生规则

**规模**：A1 942 / A2 898 / B1 802 / B2 1428 = **4070 词条**；四级并集去重 **3702 个唯一词形**（跨级重叠 2.9%–11.2%，属 CEFR 词表的正常多义现象）。与德语词表（645/797/1000/1569 = 4011）量级对齐，也符合「~4000 词」的既定口径；SPEC §4.2 原写 500/1000/2000/4000 **未采用** —— 那是纸面估算，真实数据集的分级更可信。

**字段派生（全部数据驱动）**：

| 字段 | 规则 | 关键设计理由 |
|---|---|---|
| `translation` | ECDICT 释义**按目标词性对齐取义**，剥离词性前缀、剔除 `[计]/[经]` 专业域与百科式长尾、收敛省略号占位符 | 见 §3.1 |
| `priority` | `collins` 星级 + `frq` 词频 + `oxford` 核心表 + 考纲标签 → 核心度评分 → **该等级内三分位** 30/40/30 | 见 §3.2 |
| `topic` | 词表包语义分类（规范化）→ 人工主题表（约 700 词 / 30 个语义域）→ 虚词按 pos 归入 `<pos>_basic` | 与德语 topic 命名对齐 |
| `frequency` | COCA 词频序号 → 1（最高频）~5（最低频） | 对齐德语口径 |
| `semanticConflicts` | 65 组人工整理易混词，**同等级内共现 ≥2 词时双向标注** | 见 §3.3 |

### 3.1 `translation`：词性对齐取义（本轮最重要的修正）

ECDICT 的 `translation` 是**整词条释义按义项顺序排列**（`n. …` / `vt. …` / `a. …` 各一行），而词表包标注的 `partOfSpeech` 是**该词在此等级/语境下的用法** —— 二者经常不一致。

首轮直接取首义项，产出了系统性错配：

| 词 | pos | 首轮（错误） | 修正后 |
|---|---|---|---|
| `clear` | verb | 清楚的/明确的（形容词义） | 澄清/清除障碍 |
| `light` | verb | 光/光亮（名词义） | 点亮 |
| `share` | verb | 部分/参与（名词义） | 均分/分担 |
| `musical` | adj | 音乐片/音乐舞台剧（名词义） | 音乐的/声音美妙的 |
| `off` | adv | 走开/**掉**（残片） | 走开/休息 |
| `on` | adv | **上去**（残片） | 在…之上 |

最终规则：**优先取词性匹配的义项行**（`n→noun`、`vt/vi/v→verb`、`a/adj→adj` …）→ 无词性前缀行（多为通用释义）→ 首行。
另有一条独立规则：**以省略号开头的义项是依赖上下文的残片**（ECDICT 用 `...` 表示宾语槽位），整段丢弃而非剥离圆点 —— 否则 `off` 会得到「掉」、`on` 会得到「上去」。

### 3.2 `priority`：为什么必须用等级内分位

`priority` 的语义是「学习队列顺序」，但**绝对阈值不可用**：A1 段 92% 的词都在 Oxford 核心表内，`oxford=1` 或 `frq<=3000` 之类的条件会把 A1 的 937/942 全部判为 priority 1，字段失去区分度（这是首轮实现的实际结果）。

改为：由 4 个信号合成核心度评分 → **该等级内按评分三分位切分**。产出分布 A1 283/377/282、A2 270/359/269、B1 241/321/240、B2 429/571/428，即设计目标 30/40/30。
词表数组本身也按 `(priority 升序, topic, 核心度降序)` 落盘，因此 `getUnlearnedWordsSync` 的稳定排序在**同一 priority + topic 簇内仍保持高频优先**。

### 3.3 `semanticConflicts`：同级双向标注

复用德语词表既有机制（v1.6.1 Stage 2 引入）：`getUnlearnedWordsSync` 会排除「当前 learning 词的 conflicts」，避免把易混词放进同一批 targetWords。
人工整理 65 组（`affect|effect`、`accept|except`、`quiet|quite`、`borrow|lend`、`lie|lay`、`principal|principle` …），**仅当同组 ≥2 词在同一等级内共现时**才标注。A1 35 / A2 26 / B1 6 / B2 16 词被标注。

> 实现坑：一个词可能属于多个易混组（`speak` 同时属于 `say|tell|speak|talk` 与 `speak|talk`）。首版用**覆盖**写入，后声明的小组会破坏前面的双向标注；validator 的对称性检查把它抓了出来，改为**合并 + 排序**。这条检查值得保留 —— 它抓的是人工维护数据时最容易犯的错。

## 4. 数据替换暴露的集成缺陷：课程词表脱节

`src/data/courses/en.ts` 的 20 个 Lesson `targetLemmas` 原为旧 80 词快照的切片（注释写「每 level 80 词, 取前 75」），替换词表后**19/20 个 Lesson 含该等级词表之外的词**（旧 a2/b1/b2 切片实际是字母序前缀：`accept, achieve, add, admit…`）。

这直接违背 SPEC「**词表驱动**的课程系统」的核心设计。

**修复**：按新词表重建，保持 `moduleId / order / title / theme` 全部不变（lesson id 由 `themeSlug(theme)` 派生，故既有用户进度不失效），只替换 15 个 targetLemmas。选词按 **Lesson theme 对应的主题池严格优先序**取词：

| Lesson | 主题池 | 实际取词 |
|---|---|---|
| Playing in the Park | sport → leisure → nature | lose win player draw match game party music… |
| Family Dinner Together | family → food → house | child family mother father parent girl boy wife… |
| A Day with a Pet | animal → body → house | animal dog fish bird horse chicken cat cow… |
| The Morning Commute (A2) | transport → movement → city | drive ship ride train engine bridge truck wheel… |
| An Editorial on a Civic Issue (B2) | society → business → quantity | military minister citizen freedom justice parliament… |

同级 5 个 Lesson 的词互不重复，且排除多词词形（避免 passage 命中率校验失真）。

## 6. 诚实声明（未做 / 已知限制）

- **未产出 `example` / `exampleTranslation`**：两个上游数据源均无例句语料。为 4070 词手工编造例句会产生错误示范；该字段为可选，且 `src/` 内对词表 `example` 字段**零引用**（无消费方）。留待接入真实语料后再补。
- **`topic` 在 B1/B2 仍有 40–47% 落到 `general`**（A1 已降至 12%）。原因是低等级语义域词稀疏 + 词表包本身分类粒度为 `general`。人工主题表主要覆盖高频段（对早期学习文本连贯性影响最大处）。
- **德语词表 10 处同形异义重复 lemma**（`sein` 动词「是」/限定词「他的」、`Morgen`「早晨」/「明天」等）：**既有数据，本次未改动德语文件**。校验器对 `de` 记为 warning 而非 error（`en` 强制唯一）。应用层 progress 以 `language:lemma` 为键，同形词共享状态 —— 属待后续版本决策的既存设计问题。
- **词频与 CEFR 分级来自上游语料，未逐词人工校对**。数据可信度受上游数据集质量约束。
- **未做模拟器 / 真机运行验证**：本次为纯数据 + 工程改动，验证层级为单元测试 + Web E2E + HAP 构建；模拟器运行验证仍依赖既有 `seed-and-verify.mjs`（v1.6.0 D1 清账已于 2026-09-20 达 7/7，见 `v1.6.0-EMULATOR-VERIFY-REPORT.md`）。
- **`versionCode` 校验处于跳过模式**：`expectedVersionCode` 仅覆盖 harmony major=0（T01/T03 明确断言 major≠0 返回 null，是有意设计）。当前 major=1，故 `1000065` 是按「每 minor +5」惯例设定，**不受自动校验保护**。
