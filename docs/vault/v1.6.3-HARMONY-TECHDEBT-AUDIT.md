## 1. 现状结论

Wordaydream 鸿蒙端是 **HarmonyOS 6.0.2 / API 22 的混合应用**，不是 ArkUI 全量重写：

```text
React 19 + Vite 8  (src/)  ──build:harmony──▶  harmony/entry/src/main/resources/rawfile/dist/
                                                          │
                                              ArkWeb  pages/Index.ets
                                                          │
                                          JavaScriptProxy  HarmonyBridge（20 个方法）
                                                          │
                              RDB / Preferences / TTS / 振动 / 通知 / 服务卡 / 启动参数
```

原生侧规模（本轮实测，统计口径 = 文件换行数）：

| 项 | 值 |
|---|---|
| `entry/src/main/ets` 下 `.ets` 文件 | **21 个** |
| 合计行数 | **5886 行** |

已达层级：**自动测试 + HAP 编译 + API 22 模拟器运行验证（seed-and-verify A1–A7）**。
未达层级：签名 HAP、真机（TTS / 振动 / 通知）、服务卡跨进程刷新、`reminderAgent` 权益、真实 `.env.harmony` LLM 代理 —— 明细见 CURRENT_STATUS §5「尚缺少的验证层级」。

### 3.2 待处理（按优先级）

#### P1 — `app-market/generate-images.ps1` 路径解析 off-by-one，产出「幽灵模块」

**事实**（本轮实测）：

- `harmony/app-market/generate-images.ps1:3` 用 `Split-Path -Parent (Split-Path -Parent $scriptDir)` 求 `$projectRoot`。`$scriptDir` = `harmony/app-market`，两次上溯得到的是**仓库根**而非 `harmony/`，于是第 5 行的 `$mediaDir` 落在 `<repo>/entry/src/main/resources/base/media/`。
- 该脚本已在仓库根**创建出一个与真实模块同名的 `entry/`**：仅含 `icon_background.png` + `icon_foreground.png`（各 176,626 B，合计 345 KB），由 `b112114`（v2.4.0「提交鸿蒙端移植」）批量带入版本库。
- 该目录**无任何构建引用**：`harmony/build-profile.json5:24` 的 `"srcPath": "./entry"` 相对 `harmony/` 解析，指向真实模块；`vite.config.ts:221` 的 outDir 亦指向 `harmony/entry/...`。
- 根 `entry/` 的两个 PNG 与 `harmony/app-market/icon_512.png` **字节完全相同**（md5 `19a0b822`），即脚本误写产物的直接证据。

**影响**：仓库根出现 345 KB 死结构 + `entry/` 语义歧义（根 vs `harmony/entry`）；同时**真实模块的 adaptive icon 图层从未被该脚本更新**。

**建议**：修正 `$projectRoot` 为单次上溯（`Split-Path -Parent $scriptDir`），并**征得确认后** `git rm -r entry/`。

#### P1 — 上架素材全部为同一张「生成中」占位图

**事实**（本轮实测）：`harmony/app-market/` 下 9 个 PNG（`icon_512.png` + `screenshots/` 6 张 + 根 `entry/` 2 张）**SHA256 全部相同**（`E330CD02…`，md5 `19a0b822`）。图像内容为生成服务的异步占位图 —— 画面文字为 `The image is generating... Please refresh page to preview.`；实际格式为 **JPEG 流套 `.png` 扩展名、1832×1832、不透明背景**。

**影响**：元服务上架素材就绪度为 **0**。此项已被 `harmony/app-market/README.md` 如实记录为「全部不合格」，属**已登记债**；但**根 `entry/` 下的 2 份副本未被任何文档登记**（随 P1 一并清除即可）。

**建议**：保留 README 的诚实口径；素材重做走真机/模拟器实拍，并让脚本在保存前校验 `Content-Type` 与图像尺寸，避免把占位图当产物落盘。

## 4. 前端美术表现与排版优化

### 4.1 设计系统补全

- `--color-info` 四件套（`/ -bg / -border / -text`）与 `--color-warning` 主色补入 **light / dark / paper 三主题**；此前 `var(--color-info, #3b82f6)` 这类「带兜底的引用」说明调用方早已在等这个 token。
- 新增 `--text-4xl: 2.25rem`，承接原先硬编码的 `2.25rem` 标题字号。

### 4.2 容器与排版节奏统一

| 维度 | 优化前 | 优化后 |
|---|---|---|
| 页面外壳 | `HomePage` 960px 硬编码 | `--page-max-width`（60rem），首页/课程页/词表页共用 |
| 阅读区 | `InteractivePassage` 680px、`ReadingSessionPage` 680px 各自硬编码 | `--reading-max-width`（42rem） |
| 文章标题 | `font-size: 2.25rem` / `line-height: 1.35` | `--text-4xl` / `--leading-tight` |
| 正文 | `font-size: 15px` / `line-height: 1.8` | `--text-base`（1rem）/ `--leading-relaxed`（1.75） |
| 段间距 | `margin-bottom: 1.5rem` | `--space-6` |
| 提示气泡 | 兜底色 + 硬编码 `rgba` 阴影 | `--color-surface-dark` / `--color-bg` / `--shadow-md`，深浅主题自动反色 |

### 4.3 原生侧配色与 Web 主题对齐

- `pages/Index.ets` 加载/错误覆盖层的硬编码色值（`#30302d`、`#6e6d68`、`#faf9f5`）改为 `app.color.overlay_*` 资源引用。
- `start_window_background` / `app_background` 由 `#FAF8F5` 校正为 **`#FAF9F5`**，与 Web `--color-paper` 一致，消除冷启动窗口与首页之间的白色跳变。
- dark 主题补齐 6 个资源（`start_window_background`、`app_background`、`app_foreground`、`overlay_*`），取值与 Web dark 主题 `--color-ink`(#faf8f5) / `--color-text-secondary`(#a8a29e) 对齐。

### 4.4 视觉资产（Seedream）

- 生成德语 / 英语两张课程封面插画，接入 `CoursePathPage` 课程卡片：
  - 16:9 全出血封面 + 文字区独立内边距；`object-fit: cover`；`loading="lazy"`；`alt=""` + `aria-hidden`（装饰图，语义由按钮 `aria-label` 承担）
  - hover 时封面 `scale(1.03)`，`prefers-reduced-motion` 下完全降级
- 资源管线：源图 `assets-sources/img/` → `optimize-static-assets.mjs`（`maxWidth: 1440` + WebP q80/method=6）→ `public/assets/img/*.webp`（61.4 / 66.0 KB）。
