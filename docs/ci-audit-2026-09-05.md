## 2. 三个根因详解

### 2.1 Netlify Deploy CI — vitest 版本断言失败（已复现）

```
FAIL src/package.test.ts > T22: version === "2.2.0"
AssertionError: expected '2.3.0' to be '2.2.4'
Test Files  1 failed | 71 passed (72)
```

- `d787d95` 上同时存在两个版本断言测试：
  - `src/package.test.ts`（旧）: 断言 `2.2.4` — 挂
  - `src/__tests__/package.test.ts`（新）: 断言 `2.3.0` — 过
- 根源是**硬编码版本字符串的测试**：每次版本 bump 都要记得手改，2.2.0 → 2.2.4 → 2.3.0 一路漂移。
- `b112114`（本地 HEAD，2026-08-05）删除了旧文件（diff: `src/package.test.ts | 25 -`），本地 worktree 外主工作区 1186 测试全过。**推送 `b112114` 即可修复此 workflow 的 Test 步骤**。

### 2.2 Playwright E2E — 测试断言与前端行为脱节（已复现，chromium 2/4 挂）

本地在 `d787d95` worktree 跑 `--project=chromium`（build + preview + 4 场景，37.5s）:

| 场景 | 结果 | 失败点 |
|---|---|---|
| T01 离线 banner | PASS | — |
| T02 PWA install prompt | **FAIL** | 点击 `[aria-label="设置"]` 后等 `[role="dialog"][aria-modal="true"]` 5s 超时 —— SettingsPanel 未按 spec 预期弹出（选择器/交互路径与源码脱节；元素本身在 HomePage.tsx:194 与 SettingsPanel.tsx:625 都存在） |
| T03 SW 注册 | PASS | — |
| T04 生成文本 | **FAIL** | `expect(body).toContainText('garden')` 失败 —— 页面渲染的是内置演示文本 "The Quiet Revolution" 而非 mock proxy 返回的 "A Quiet Garden" |

**T04 的设计前提错误**：`router.ts:156` — `if (!settings.enabled || settings.provider === 'mock') return mock 路径`。CI/webServer 注入 `VITE_LLM_PROVIDER: 'mock'` 后，前端**根本不发 `/api/llm-proxy` 请求**（本地 MockLLMProvider 直接产出 demo 语料），spec 里 mock proxy 的 `page.route` 永远不会被命中。chromium 已 2/4 挂 → CI 4 浏览器 × 4 场景矩阵必然红；firefox/webkit 大概率还叠加慢启动/超时（job timeout 仅 20min）。

另注：`b112114` 新增的 `e2e/harmony.spec.ts`（8 场景）**不在 `testIgnore` 里**（只排除了 `harmony_full.spec.ts`），推送后 Web CI 矩阵会多跑 8×4=32 个用例，其中 H03 与 T04 是同款生成流程，会继承同样的失败。

### 2.3 Lighthouse CI — assertion 评分不达标（已复现评分）

本地以与 `.lighthouserc.cjs` 相同参数（4 categories、mobile 412x823@1.75、simulate throttling）对 `npm run build` 产物单次跑分：

| 类别 | 实测 | 阈值 (5% buffer 后) | 判定 |
|---|---|---|---|
| performance | **64** | ≥ 76 | **FAIL** |
| accessibility | 94 | ≥ 85 | pass |
| best-practices | 100 | ≥ 85 | pass |
| seo | **83** | ≥ 85 | **FAIL** |

失分项拆解：
- performance 64: LCP **6.0s**（weight 25, score 13）、FCP 3.8s（w10, s28）、SI 6.5s（w10, s38）。产物 precache 2310KB，最大 chunk `data-parsers` 303KB(gzip 73KB)、`b2` 206KB、`react-vendor` 178KB —— 语料/解析器未按路由懒加载到位。
- SEO 83: `public/robots.txt` **不存在**、`index.html` **无 meta description**（两项 score 0，修掉即回 100）。
- A11y 94: color-contrast 一处对比度不足。
- CI runner 单核更快，分数会比本地高一些，但 LCP 6s 量级的差距靠机器速度弥补不了 —— **CI 每次 assertion error → `lhci autorun` exit 1**。
- 已排除: `temporary-public-storage` 服务仍在运营（Eris Ventures，官方 services-disclaimer 页确认），upload 不是死因。

## 3. 结构性/工程问题

1. **红灯 7 周无人管**: schedule 任务每周在必败代码上继续烧 runner；无 branch protection / required checks，红灯照常合入。
2. **修复停在本地**: `b112114` 未推送；工作区另有 ~80 个文件未提交（v0.4.0 进行中），本地与远程已实质分叉一个月。
3. **tsc 隐患（下一个引爆点）**: 当前工作区 `npx tsc -b` **exit 1，34 个错误** —— `api/llm-proxy.ts` 12 个（`data: unknown`）、`src/data/wordlists/index.ts` 8 个（zod v4 schema 类型）、`src/workers/llmJsonWorker.ts` 5 个、`vite.config.ts` 若干（相对导入缺扩展名 + 隐式 any）。一旦推送，Netlify CI 修好 Test 后会立刻挂在 TypeScript check。
4. **版本断言测试的反模式**: 见 2.1，建议删除或改为"CHANGELOG 顶部版本 === package.json version"的动态对比。
5. **VITE_APP_VERSION 三处硬编码 '1.5.1'**: lighthouse.yml / playwright.yml(webServer) / netlify-deploy.yml，与 package.json 2.3.0 严重脱节（产物内嵌版本号失真）。
6. **双 Netlify 部署路径**: netlify.toml 官方集成 + workflow deploy job 冗余，后者从未跑过。
7. **无 concurrency 取消**: 三个 workflow 均未配 `concurrency`，连环 push 会排队重复跑。
8. **文档漂移**: docs/OPERATIONS.md §3 仍写着 `treosh/lighthouse-ci-action@v11` + `lighthouse.config.js`，v2.4.0 实际已换 `npx lhci autorun --config=./.lighthouserc.cjs`。
9. **Playwright job 超时偏紧**: webServer build（上限 300s）+ npm ci + 4 浏览器 × 4~12 场景，`timeout-minutes: 20` 在 linux runner 上余量很小。
10. **本地 node_modules 与 package-lock 漂移**: 主工作区跑不了 1.62.1 对应的 chromium-1234（缓存停留 1217/1223），说明本地 e2e 已一段时间没跑过。

## 4. 修复建议（按优先级）

**P0 — 让 CI 变绿的最短路径**
1. 提交并推送 `b112114`（含工作区 v0.4.0 改动需先收尾）→ Netlify CI Test 转绿。
2. 修 34 个 tsc 错误（zod v4 类型收窄、`api/llm-proxy.ts` unknown 处理、vite.config 扩展名/any）→ TypeScript check 转绿。
3. Lighthouse 快赢: 新增 `public/robots.txt` + `index.html` meta description（SEO 83→~100，10 分钟工作量）；performance 先把阈值降到现实水位（如 `minScore: 0.55`）让 CI 先绿，再按"LCP: 语料 chunk 懒加载 + 字体/关键资源 preload"逐项收紧。
4. Playwright: 重写 T02（对齐 SettingsPanel 实际触发路径，建议加 `data-testid`）与 T04（改为断言 demo 文本 "The Quiet Revolution"，或让 spec 在 provider=mock 时直接验证 mock provider 短路路径）；`playwright.config.ts` 的 `testIgnore` 补 `harmony\.spec\.ts`（它有独立 config）。
5. Playwright `timeout-minutes` 提到 30，并加 `concurrency` 组。

**P1 — 防复发**
6. 删除/重构版本断言测试（见 4）；`VITE_APP_VERSION` 改由构建脚本从 package.json 注入。
7. 三个 workflow 加 `concurrency: { group: ci-${{ github.ref }}, cancel-in-progress: true }`。
8. main 开 branch protection + required checks（lint/test/typecheck 至少）。

**P2 — 清理**
9. 二选一移除 Netlify 部署路径（建议删 workflow deploy job，保留官方 Git 集成 + workflow 只做 CI）。
10. 同步 docs/OPERATIONS.md 与实际 workflow；本地重装 `npx playwright install chromium` 对齐 1.62.1。
